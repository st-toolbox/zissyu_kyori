# 実習配置アプリ

学科の先生が、臨床実習の配置（評価・総合・見学）を決めるためのアプリ。
学生ごとに、各施設まで片道何分かかるかを出し、宿泊にならない組み合わせを探す。

- 画面：GitHub Pages（`index.html` `app.js` `style.css`）
- データ：Firebase Realtime Database（`zissyu-kyori`）。ログインは Google
- 経路計算：Google Apps Script（`gas/Code.gs`）。何も保存しない

## 片道の出し方

片道 ＝ ①学生の駅まで（本人の申告）＋ ②駅→駅（Google Maps の電車）＋ ③施設の駅から（徒歩、またはバス・送迎の分数）

- 学生の住所は持たない。持つのは「ふだん使う駅・駅までの手段と分数」と「実家からの実習 可/不可（可なら実家の駅）」だけ。学生には「通学の確認票」（5. 印刷）に書いてもらう
- 駅に着きたい時刻 ＝ 始業 − ③ − ゆとり（既定5分）。5分きざみで切り下げる
- 駅→駅の結果は年度をまたいで使い回す（同じ駅・同じ時刻なら Maps に聞くのは1回）
- 判定：◎60分以内／○80分以内／△90分以内／×それ以上（宿泊）。分数は設定で変えられる
- 車で直接通う学生は、住所を画面に入れて計算するだけで保存しない（保存するのは施設ごとの分数）

## はじめて置くとき

1. **規則**：Firebase のコンソール → Realtime Database → ルール に `database.rules.json` の中身を貼って公開する
2. **最初の先生**：アプリを開いて学校のアカウントでログインすると、未登録の案内と UID が出る。コンソールのデータで `teachers` の下にその UID の名前で1件足す（中身は `email: 自分のメール`）。2人目からはアプリの「先生」画面で招待する
3. **経路計算（GAS）**：
   - script.google.com で新しいプロジェクトを作り、`gas/Code.gs` を貼る
   - デプロイ → 新しいデプロイ → 種類「ウェブアプリ」、実行するユーザー「自分」、アクセスできるユーザー「全員」
   - 出た URL（`https://script.google.com/macros/s/…/exec`）をアプリの「設定」に入れる
   - 先生かどうかは、送られてきたログインの証明で Firebase の `teachers` を読めるかで確かめる（合言葉は使わない）
4. **施設**：「古い控えから施設を取り込む」（旧アプリの書き出し JSON。施設だけ読み、学生は読まずに捨てる）か、「表から貼り付け」。そのあと「駅の下書きを出す」で駅を下書きし、先生が確かめて直す

## 毎年の流れ

1. 年度を選ぶ（4月始まり）。空の年度は、前の年度の受入人数・始業を写して始められる
2. 施設：受入人数と始業を直す
3. 確認票を印刷して配り、回収したら学生を入れる（表から貼り付けか1人ずつ）
4. 計算する（まだの分だけ Maps に聞く）
5. 割り振り：学生を選ぶと候補の施設が近い順に出る。配置したら種別ごとに確定。確定後に変えるときは理由を残す
6. 配置の一覧を印刷する

## 守ること

- このリポジトリは公開。学生・先生の名前・メール・学籍番号・住所・名簿の形のファイルを入れない（`.gitignore` で csv・xlsx・pdf・json を止めてある）
- 見本のデータは架空で作る（「学生A」「S0001」）
